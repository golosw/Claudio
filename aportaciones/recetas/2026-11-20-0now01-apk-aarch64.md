# Receta aportada — compilar una APK en Termux aarch64 sin Gradle

| Dato | Valor |
|---|---|
| Tipo | receta |
| Probado en | Android/Termux `aarch64` · 2026-11-18 (reescrito y anonimizado 2026-11-20) |
| Perfil de plataforma | terminal |

## Problema u objetivo

Compilar una APK en un equipo `aarch64` donde los build-tools de Google y AGP son `x86_64` y no arrancan sin emulación.

## Pasos

1. No instalar Gradle/SDK oficial para este fin: `aapt2` y `d8` de Google no corren en `aarch64` sin qemu.
2. Usar el toolchain nativo: `aapt2`, `kotlinc`, `d8`, `apksigner`, `keytool` y `zip`. Instalar con `pkg install kotlin aapt2 apksigner d8`.
3. Si `aapt`/`aapt2` fallan con `cannot locate symbol _ZNSt6__ndk113__hash_memoryEPKvm`, actualizar `libc++` con `pkg install -y libc++`.
4. `android.jar` es independiente de arquitectura: descargar el ZIP de plataforma desde el repositorio oficial de Google y extraer `android-35/android.jar`, sin `sdkmanager`.
5. Secuencia: `aapt2 link` (manifiesto → APK base) → `kotlinc -jvm-target 17 -classpath android.jar:kotlin-stdlib.jar` → `d8 --lib android.jar --min-api 23` → `zip -q unsigned.apk classes.dex` → `apksigner sign` → `apksigner verify`.
6. `kotlin-stdlib.jar` está bajo `$PREFIX/opt/kotlin/lib/`. Derivar `$PREFIX` desde la ruta de `kotlinc`, no hardcodearlo.
7. `kotlinc` imprime un aviso de `jansi`/`libc.so.6` en Termux; es cosmético, la compilación termina bien.

## Cómo se comprueba

`apksigner verify`, `aapt2 dump badging`, `unzip -l` (classes.dex presente) y `unzip -p ... classes.dex | grep -ao` buscando el nombre de clase. La instalación visual la confirma la persona.
